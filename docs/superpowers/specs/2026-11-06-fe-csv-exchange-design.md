# FE CSV exchange format, importer and node assessment: design

Issue: [andreachiocca/multiaxial-fatigue#19](https://github.com/andreachiocca/multiaxial-fatigue/issues/19)
(comment by the maintainer proposing a CSV export, 5 November 2026). Date: 2026-11-06. Status: draft for
approval, nothing built. Builds on the FE local-history interface
([design](2026-11-05-fe-local-history-interface-design.md), `src/multifat/fe/`) and the load-history
bridge ([design](2026-11-05-load-history-bridge-design.md), `src/multifat/history/`).

## Intent and why

The HDF5 history file built for issue 19 is a storage format that adapters are meant to write, and
no adapter for a real solver exists: an FE engineer has no practical way to get data in. The
maintainer proposes the missing front door: **one CSV per simulation, in a fixed format that the user
(or a short solver script) exports**, with named columns and a metadata header that states the things
FE exports silently get wrong. This work adopts it as the **recommended format for users to
produce**, converts it by a streaming importer into the HDF5 file (which stays the internal canonical
store), and joins it to the load-history assessment so that a CSV of an FE run can be assessed node by
node. It also answers the maintainer's open point, how a solver step maps to a fatigue cycle.

    solver / script -> CSV (this format) -> streaming importer -> HDF5 history file -> TimeHistory per node
                    -> assess_history (rainflow, damage per event, Miner) -> table of damage and life per node

## Decided with the user (2026-11-06)

- Adopt the maintainer's CSV as the user-facing exchange format; keep HDF5 as the engine; keep the
  VTK importer as a secondary route (ParaView exports).
- Do everything discussed: the merged specification, an example file, the importer with a round-trip
  test, the file-format extensions (instance and material per node, elastic and plastic strain,
  temperature, analysis metadata), elastic-strain derivation for linear-elastic runs, the step-role rule
  with unit-case superposition, and a node assessment driver. Exporter code for Ansys and Abaqus
  needs a licence to test; the maintainer is asked for tested recipes.

## The two approaches merged

From the maintainer, adopted: CSV long format (one row per node per step) with named columns, never
positional; solver column aliases; shear-convention declaration and conversion; global Cartesian frame
required of the exporter; `# key: value` metadata header in the style of `tests/data/papers/*.csv`;
`instance` and `material` columns; optional `Eel`, `Epl` and `T`; node sets rather than whole meshes; the
averaging warning (averaging across a material or section interface is wrong); stresses alone suffice for
a linear-elastic run (elastic strain derived from `E` and `nu`); keeping the CSV compatible with the
time-history work.

From the existing design, added to the format: separate required units (`stress_unit`, `length_unit`,
`time_unit` when a time column exists) instead of one `units` key; an integrity header (`n_nodes`,
`n_steps`) and a full location-by-step grid with unique `(instance, node_id, material, step)` keys, so a
truncated or ragged file is refused; no inference anywhere (an unknown column, a missing required header key or a
non-global frame is an error); round-trip numeric precision (17 significant digits); symmetric and finite
tensors; a stabilised-cycle requirement for elastic-plastic runs; the `complete`-flag HDF5 output.

## Goals

1. **Format specification** `docs/fe-csv-format.md`: header keys and values, columns and aliases, rules,
   sort order, size guidance, solver checklists (what to set in Ansys and Abaqus so that the export is
   global, averaged within materials and in the declared convention), a minimal example.
2. **Example file** (a few nodes, two steps, header) generated by the synthetic tube generator, so the
   example has an analytical oracle, plus variants in the Abaqus and Ansys naming, in engineering shear,
   in Pa and m, in step-major and node-major order.
3. **Importer** `multifat.fe.csvio.import_fe_csv(csv_path, out_path, ...)`: parses the header, validates
   it, maps named columns (canonical names and a documented alias table for Abaqus `S11 S22 S33 S12 S13
   S23`, `EE..`, `PE..` and Ansys `SX SY SZ SXY SYZ SXZ`, `EPELX..`, `EPPLX..`, `TEMP`), converts units and
   the shear convention, checks the frame, streams the rows into the HDF5 file, and records provenance
   (file hash, header, alias mapping used).
4. **Writer helper** `multifat.fe.csvwriter`: standard-library-only functions that a solver-side Python
   script (Abaqus, PyAnsys) can copy or import to write a compliant file (header, rows, precision).
5. **File-format extensions (version 1.1, additive)**: per-location `instance` and `material`; optional
   `strain_elastic`, `strain_plastic` and `temperature` fields next to the total strain; metadata
   `analysis_type`, `cycle`, `step_role`, `load_description`; averaging values extended to say whether
   averaging stayed inside a material. Version 1.0 files still read.
6. **Elastic-strain derivation**: for `analysis_type: linear_elastic` without strain columns, derive the
   elastic strain by Hooke's law from `E` and `nu` supplied per material (`material` column selects them;
   they can come from the workbook materials); recorded as derived. Refused for elastic-plastic runs.
7. **Step role and node assessment**: header `step_role` is `time_sample` (the steps are samples of one
   load history, in time or step order) or `unit_case` (each step is a unit load case; a load-function
   file combines them, linear elastic only). `multifat.history.nodes`: build a `TimeHistory` per selected
   node from either, and `assess_nodes(...)` that returns damage and life per node (with instance and
   material), over a node subset in bounded memory.
8. **Alignment** of the single-location `TimeHistory.from_csv` with the same column names (`S_xx`, `Eel_xx`,
   `time`), keeping the old short names accepted.
9. Tests (round trips of units, frame, shear convention and aliases; refusals; streaming memory; end to
   end from CSV to assessed nodes), documentation, decision log, checkpoint, and a reply to the maintainer.

## Non-goals and anti-goals

- No element data, integration-point values, connectivity or inputs for nonlocal or gradient methods in
  this version (`location_kind` is `node`); they are listed as later.
- No Parquet in this round; the format leaves room for it (the header, not the container, carries the
  meaning). No solver-specific code that cannot be tested here: Ansys and Abaqus exporter recipes are
  **checklists plus the writer helper**, and tested recipes are requested from the maintainer.
- No inference of units, frame, shear convention, averaging or analysis type. No automatic fix of an
  averaged interface. No silent use of superposition for elastic-plastic data.
- No harmonic reduction of a sampled non-proportional cycle in this round (a candidate follow-up that
  needs the workbook harmonic convention checked); non-proportional histories keep the explicit refusal
  or recorded approximation of the load-history bridge.
- No change to any model, calibration record or existing CSV; existing numbers unchanged (snapshot).
  No claim of validation.

## Constraints

- Repository conventions as before: notation rows first, numpydoc, black 100, ruff, MPa and mm, tensor
  shear internally, decisions in `docs/decision-log.md` (after `d085`), checkpoint, commits local, no push,
  no attribution lines. `h5py` stays optional (extra `fe`); the writer helper and the header parser need
  only the standard library; pandas is already a dependency.
- Version 1.0 HDF5 files and the VTK importer keep working unchanged.
- The CSV is text: write 17 significant digits; read with an explicit dtype; do not rely on a locale.

## Design

### The CSV

Header: lines starting with `# key: value`, before the column line; then one comma-separated column line;
then rows. UTF-8, `\n`, decimal point, no quoting needed. Required header keys: `format` (value
`multifat-fe-csv 1.0`), `solver`, `solver_version`, `stress_unit` (`Pa`, `kPa`, `MPa`, `GPa`, `psi`, `ksi`, `N/mm^2`), `length_unit`
(`m`, `cm`, `mm`, `in`, `ft`), `coordinate_system` (`global_cartesian`), `averaging` (`none`,
`nodal_average_within_material`, `nodal_average_global`, `extrapolated`), `analysis_type`
(`linear_elastic`, `elastic_plastic`), `step_role` (`time_sample`, `unit_case`). Required when relevant:
`strain_convention` (`tensor` or `engineering`) and `strain_unit` (`1`, `mm/mm`, `m/m`, `percent`,
`microstrain`) if any strain column exists; `cycle` (`stabilised`, an
integer, or `not_applicable`) for `elastic_plastic`, which must be `stabilised`; `time_unit` if a `time`
column exists. Free text: `load_description`, `model`, `source`, `notes`. Optional integrity: `n_nodes`,
`n_steps`, `temperature_unit`.

Columns: `node_id` (integer), optional `instance` and `material` (text), `step` (integer, starts anywhere,
distinct per load step), optional `time`, `x`, `y`, `z`, `S_xx S_yy S_zz S_xy S_yz S_xz`, optional
`Eel_xx ... Eel_xz`, `Epl_xx ... Epl_xz`, `T`. Aliases are accepted by exact name (case-insensitive) from a
table; a file that has both a canonical column and its alias is refused. Rows are step-major (all nodes of
one step, then the next step) for streaming; a node-major file is read in memory up to a stated row limit.
A **location** is the triple `(instance, node_id, material)`: with `nodal_average_within_material` a node
on a material interface appears once per material, each with its own values. The grid must be complete (every
location has every step) and the keys `(instance, node_id, material, step)` unique; an absent `instance` or
`material` column counts as the empty string. `n_nodes` counts distinct locations.

### The importer and the file

`import_fe_csv` validates the header and columns before reading rows, then streams step by step in chunks
into `HistoryWriter` (extended): peak memory is one step. Strain: total mechanical strain is `Eel + Epl`
when both are given, `Eel` alone for elastic data, and `Epl` alone is refused unless the elastic part can
be derived; engineering shear is halved for strain only. The file keeps `strain_elastic`, `strain_plastic`
and `temperature` when present. `instance` and `material` become per-location string arrays; the
uniqueness rule of the file is the location triple (`location_id` stays the integer node label and is no
longer unique on its own). `averaging: nodal_average_global` together with more than one
material or instance is refused unless `allow_global_average=True`, which is recorded.

### Steps, cycles and nodes

`step_role: time_sample`: each node's series over the steps is a `TimeHistory` (axis from `time` if
present, else the step index with `axis_kind="cycle"`). Two steps, max then min, are the two-state case
and give exactly one cycle under the default residue policy; a sampled cycle goes through counting;
proportional histories are exact, others are refused or approximated explicitly. `step_role: unit_case`:
each step is a unit load case `S_k`; a load-function CSV (`time, f_1 ... f_K`) gives
`S(t) = sum_k f_k(t) S_k` per node, linear elastic only (refused otherwise). `assess_nodes` iterates a
node subset in chunks, builds the histories, calls `assess_history` and returns one row per node.

## Verification

1. **Round trips against the analytical tube** for every convention: canonical, Abaqus and Ansys names;
   tensor and engineering shear; `Pa`/`m` and `MPa`/`mm`; step-major and node-major; with and without
   `instance`, `material`, `time`; with `Eel`/`Epl`/`T`.
2. **Refusals with diagnostics**: missing or invalid header keys, a missing unit, a non-global frame, a
   missing `strain_convention`, a canonical column and its alias together, an unknown column, truncated or
   ragged grid (against `n_nodes` and `n_steps`), duplicate keys, non-symmetric or non-finite tensors,
   elastic-plastic without `stabilised`, global averaging across materials, unit cases on elastic-plastic
   data, `Epl` without a way to get `Eel`.
3. **Derived elastic strain** equals Hooke by hand for each material; marked as derived.
4. **File extensions**: version 1.1 round trip of instance, material, split strain and temperature;
   version 1.0 files from the earlier tests still open.
5. **Streaming**: peak memory independent of the number of nodes at fixed step size (tracemalloc test) and
   a larger opt-in case.
6. **End to end**: an example CSV imported and assessed node by node reproduces the direct
   `assess_history` result of the same histories; `unit_case` superposition equals the directly built
   history; two steps give one cycle and the constant-amplitude value.
7. **Writer helper** produces files the importer accepts and needs only the standard library.
8. Isolation, regression snapshot unchanged, full suite, black, ruff, `check_docs`.

## Units and xarray (decision)

Units are handled by small, explicit tables at the import edge (stress to MPa, length to mm, strain to
dimensionless), not by `pint` or `xarray`: xarray stores a `units` attribute but does not convert or
check it, and unit-aware arrays would need `pint` and `pint-xarray`, a heavy dependency for a closed
problem. The tables now include the US-customary units that solver models often use. An optional
`xarray` view of a history (dimensions location, step, component, with node id, instance, material,
coordinates and time as coordinates, units in the attributes) is a possible later extra; it does not
replace the HDF5 store (completeness flag, step-by-step streaming writes, bounded-memory reader).

## Later (not in this round)

Element and integration-point data and connectivity; inputs for nonlocal and gradient methods; Parquet;
tested Ansys and Abaqus exporter scripts (from the maintainer); harmonic reduction of a sampled cycle to
`S_mean`, `S_sin`, `S_cos` for non-proportional single-harmonic loading; multiaxial counting (follow-ups
F1-F8 of the load-history bridge).

## Decisions from the builder check (assistant's calls)

1. **Setups per material.** `assess_nodes` takes `materials: Mapping[str, MaterialSetup]`, where
   `MaterialSetup(model, params, curve, E=None, nu=None)`; a single `MaterialSetup` applies to every node. Nothing
   is resolved from the workbooks in this round (a resolver is a follow-up, once the maintainer confirms
   `material` is a workbook ID). A node whose material has no setup gets the status `no_material_setup`; the run
   continues. Elastic strain is derived **at import** when `import_fe_csv` is given
   `elastic_constants: Mapping[str, tuple[E, nu]]`, and stored with `strain_kind = "derived_linear_elastic"` (or
   `"derived_elastic_part"` for the elastic part of an elastic-plastic run); without constants a stress-only file
   still imports and strain-needing methods are refused later.
2. **Interface nodes.** One row per material at an interface (the location triple above); `select_by_ids` gets
   optional `instance` and `material` arguments and returns every match when they are omitted, which the
   documentation states.
3. **Strain columns.** Accepted: `Eel` and `Epl` (total = sum), a total `E_xx ... E_xz` (Abaqus `E11 ...`) taken
   as total mechanical strain, `Eel` alone (elastic data), and `Epl` alone **when `elastic_constants` give the
   material's `E` and `nu`**: the elastic part is then derived by Hooke from the stress (isotropic elasticity)
   and recorded as derived. Elastic-plastic data with no strain column at all is refused. Elastic derivation
   without any strain column is allowed only for `linear_elastic`.
4. **Step order.** Load cases are ordered by ascending `step` value; steps need not be contiguous, duplicates
   are refused. A step-major file must list steps ascending (streaming); a node-major file is sorted in memory.
   A `time` column must be strictly increasing along that order, else the file is refused, never re-sorted.
   In the load-function CSV for `unit_case`, columns are `time` (or `index`) and `f_<step>` named by the step
   value of the unit case; a missing or extra function column is an error; matching is by name, never by
   position.
5. **Refusals in a node run.** `assess_nodes(..., on_refusal="record")` (default) records one row per node with a
   `status` (`ok`, `ineligible: <reason>`, `no_material_setup`) and continues; `on_refusal="raise"` aborts at the
   first refusal. `allow_nonproportional_approximation` and the other assessment options are passed through for
   the whole run; unexpected exceptions are not caught.
